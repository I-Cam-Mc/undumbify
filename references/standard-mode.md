# STANDARD mode

Use STANDARD for ordinary substantive requests where the interpretation is broadly visible but scope, evidence, constraints, output or success may still need confirmation.

## Stop 1: Intent echo

Give the core one-paragraph readback and wait. This catches semantic errors before retrieval or detailed questions are shaped around the wrong interpretation.

## Context and decisions

After confirmation:

1. Retrieve only context likely to change the prompt.
2. Resolve discoverable facts through read-only work when cheaper than asking the user.
3. Ask no more than five highest-value questions in one compact round.
4. Present no more than three provisional consequential assumptions.
5. Offer only success checks whose selection would affect execution or verification.

External discovery is optional, not standard ceremony. Use it only when a current fact or named capability gap could materially change the prompt.

## Stop 2: Decision round

Combine the questions, provisional assumptions and proposed success checks. Use A-D choices where they reduce effort, allow free text, and put recommendations below the options.

After the answers, render without adding a routine third stop. If an answer exposes a new consequential decision that is genuinely unresolved, do not call the prompt confirmed. State the blocker and offer the optional additional clarification round.

## Render

Write the target-state checksum immediately above the copy-ready prompt. Include confirmed requirements and assumptions, but do not copy the clarification conversation into the prompt.

STANDARD should normally recommend Low effort. Escalate to Medium only when the eventual task retains meaningful ambiguity, research synthesis, interacting constraints, or verification demands after clarification.
